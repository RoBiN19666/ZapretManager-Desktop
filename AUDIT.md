## 0. Вердикт

Проект заметно сильнее типичного «менеджера для zapret»: один exe без зависимостей, аккуратный разбор реальных `general*.bat`, продуманный механизм сохранения пользовательских правок в официальных списках, обновление с резервной копией, собственные WinForms-контролы, тёмная тема, DPI-масштабирование и продуманная диагностика.

Но в текущем виде **эксплуатировать его как «боевой» инструмент рискованно**: есть несколько путей тихой потери данных, мёртвая заявленная функциональность, обновления, которые могут «успешно» оставить систему в нерабочем состоянии, и целый класс зависаний UI из-за синхронных операций в потоке интерфейса.

## 2. Критические дефекты

### C1. `SetIpsetMode` уничтожает полный IP-список при `any → none`

**Где:** `src/Core.cs:1772-1815` (ключевые строки 1783-1800), вызывается из `PageOverview.cs:273-280` (тумблер «Полный IP-список») и `PageSettings.cs:401-409`.

```csharp
else if (current == "any")
{
    if (File.Exists(Install.IpsetBackup))
    {
        if (File.Exists(Install.IpsetFile)) File.Delete(Install.IpsetFile);
        File.Move(Install.IpsetBackup, Install.IpsetFile);   // полный список вернулся в рабочий файл
    }
    else return "Нет резервной копии списка. ...";
}

if (mode == "none")
{
    File.WriteAllText(Install.IpsetFile, "203.0.113.113/32\r\n", ...);  // ...и тут же затирается заглушкой
}
```

**Что происходит:** в режиме «любые IP» полный список лежит в `lists/ipset-all.txt.backup`, рабочий файл пуст. Пользователь переключает режим на «без фильтра по IP» (`none`): код сначала **перемещает** резервную копию в рабочий файл (`.backup` исчезает), а затем **перезаписывает** рабочий файл заглушкой `203.0.113.113/32`. Итог — полный список (в реальной установке 572 927 байт / 33 048 строк) уничтожен безвозвратно; восстановить можно только повторным скачиванием.

**Дополнительно:** при `mode == "loaded"` и отсутствии `.backup` метод молча ничего не делает, но возвращает «Готово: загружен полный список» (строки 1805-1814). `PageSettings.ApplyIpsetMode` при этом всегда показывает `LogLevel.Ok` (`PageSettings.cs:405-406`).

**Исправление:** не перемещать `.backup` до успешной записи; писать через temp + `File.Replace`; для `loaded` без копии возвращать явную ошибку; сделать `SetIpsetMode` идемпотентным и атомарным.

### C2. «Принять как официальное» удаляет добавленные домены

**Где:** `src/ListChanges.cs:348-365`, вызов — `PageLists.cs:569-584`.

```csharp
List<string> all = ParseEntries(officialLines);
foreach (string b in blockEntries) AddUnique(all, b);   // добавления попали в baseline
BaselineEntries = all;
...
string text = ComposeText(officialLines, new List<string>());  // ...но в файл не пишутся

```

**Что происходит:** пользователь добавляет `my-site.example` в официальный список (строка уходит в блок `# >>> Zapret Manager`), затем нажимает «Принять как официальное». **Исправление:** `ComposeText(officialLines, all)` либо включать `blockEntries` в официальную часть; после действия перезагружать `_changes` и проверять, что `Removed` пуст.

### C3. Самообновление ломается на путях с кириллицей и не перезапускает приложение

**Где:** `src/SelfUpdate.cs:256-281`.

```csharp
sb.AppendLine("copy /y \"" + newExe + "\" \"" + exePath + "\" >nul");
...
File.WriteAllText(script, sb.ToString(), Encoding.Default);       // ACP (обычно CP1251)
ProcessStartInfo psi = new ProcessStartInfo("cmd.exe", "/c \"" + script + "\"");
```

**Что происходит:** `apply-update.cmd` содержит кириллические пути (`C:\Проекты дипсик\...`, `C:\Users\Иван\AppData\Local\Temp\...`). Файл записывается в системной ANSI-кодировке (CP1251), а `cmd.exe` читает пакетные файлы не в ACP: на проверенной машине — как UTF-8, на «классической» русской Windows — в OEM CP866. В обоих случаях кириллица декодируется неверно, `copy` не находит файл и завершается с кодом 1. Скрипт удаляет себя, приложение к этому моменту уже вызвало `Application.Exit()` (`PageUpdate.cs:442`) — **программа закрылась и больше не запустилась**, обновление не применилось.

**Воспроизведено:** `.cmd` в CP1251 с кириллическим путём → `exit=1`, целевой файл не создан; тот же `.cmd` в UTF-8 → успех. На машине с русским именем пользователя или папкой установки это массовый сценарий (текущий репозиторий сам лежит в `C:\Проекты дипсик\...`).

**Исправление:** не использовать `cmd.exe` и `copy`; применить `MoveFileEx`/`PendingFileRenameOperations` или отдельный updater; если cmd неизбежен — писать в OEM-кодировке консоли (`GetConsoleOutputCP`/`CultureInfo`), а не `Encoding.Default`, и проверять `%errorlevel%`. Дополнительно: не выходить из приложения, пока скрипт не подтвердил успешную замену (файл-маркер).

### C4. Фоновый сторож сайтов не запускается

**Где:** `src/Shell.cs:1224-1238` (определение `StartSiteGuard`), вызовов нет; `PageSites.cs:278-352` только включает журнал DNS и сохраняет `SiteGuard=1`.

**Что происходит:** README (раздел «Фоновый сторож сайтов») и `docs/guide.md:126-137` обещают автоматическую слежку за DNS-журналом, проверку доменов и добавление заблокированных в `list-general-user.txt`. На практике `_guardTimer` не создаётся никогда (`StartSiteGuard` не вызывается ни из `OnShown`, ни из страницы), `SiteGuard.Process` вызывается только из мёртвой ветки Shell. В live-конфиге пользователя `SiteGuard=1`, журнал включён, но в `manager.log` за всё время работы нет ни одной записи сторожа.

**Дополнительно:** `--guard-once` (`Program.cs:112-120`) читает хосты в `guardHosts` и **выбрасывает результат**, не вызывая `SiteGuard.Process`, и не делает `return` — после этого запускается обычный UI. То есть и CLI-режим из `docs/guide.md:268` не работает.

**Исправление:** вызвать `StartSiteGuard()` из `OnShown` (или из `PageSites` при включении), а `--guard-once` должен выполнить `SiteGuard.Process` и выйти. Либо удалить функцию из документации.

### C5. `ipset-all.txt` невозможно сохранить со страницы «Списки»

**Где:** `PageLists.cs:235` (`AddFile(..., official: true)`), `:292` (`markable = f.Official && ListChanges.IsOfficial(...)`), `:473-477`; `ListChanges.cs:31-34` (в `OfficialFiles` нет `ipset-all.txt`).

```csharp
bool markable = f.Official && ListChanges.IsOfficial(Path.GetFileName(f.Path));

if (f.Official && _changes == null)

    Shell.Notify("Официальные списки можно править — изменения будут помечены. Перезагрузите страницу.", LogLevel.Warn);
```

**Что происходит:** `ipset-all.txt` помечен как официальный, но не входит в `OfficialFiles`, поэтому `_changes` для него всегда `null`. ### C6. Несохранённые правки списков теряются без предупреждения

**Где:** `PageLists.cs:77` (`SelectedIndexChanged → LoadSelected`), `:269-290` (перезапись `_editor.Text`), `Shell.cs:714-747` (`OnFormClosing` не проверяет `_dirty`); флаг `_dirty` используется только в тексте «Есть несохранённые изменения» (`PageLists.cs:333`).

### C7. «Причесать строки» портит CIDR/IPv6 и снимает якоря `^`

**Где:** `ListAudit.cs:167-187` (`CleanToken`), `:219-249` (`Tidy`); кнопка — `PageLists.cs:139-143`, `:634-650`, сохранение — `:454-516`.

```csharp
int slash = t.IndexOfAny(new char[] { '/', '?', '#' });
if (slash >= 0) t = t.Substring(0, slash);   // 10.0.0.0/8 → 10.0.0.0
...
if (t.StartsWith("^")) t = t.Substring(1);   // ^dns.google → dns.google
```

**Что происходит на реальных файлах:**

| Было | Стало после «Причесать» |
|---|---|
| `10.0.0.0/8` | `10.0.0.0` (маска потеряна) |
| `192.168.0.0/16` | `192.168.0.0` |
| `fc00::/7` | удалено (после обрезки по `/` и `:` остаётся `fc00`) |
| `fe80::/10` | удалено |
| `^dns.google` | `dns.google` (якорь «только этот хост» снят) |

`lists/ipset-exclude.txt` в поставке состоит **целиком** из CIDR (11 строк), а `list-general.txt` начинается с восьми `^...`-записей. «Причесать» + «Сохранить» на `ipset-exclude.txt` превращает подсети в отдельные IP, а на `list-general.txt` — меняет семантику исключений и записывает `^`-строки как «удалённые вами» (потому что baseline содержит `^dns.google`, а после причёски в файле `dns.google`).

**Проверено harness-ом:** `Tidy("10.0.0.0/8\r\n^dns.google\r\nfc00::/7\r\nexample.com")` → `10.0.0.0 | dns.google | example.com`, `removed=1`, `changed=2`.

**Исправление:** формат-зависимая причёска: для `*ipset*` валидировать `IPAddress`/CIDR и не трогать `/` и `:`; для доменных списков сохранять `^`; не применять доменную эвристику к IP-файлам. Перед сохранением показывать diff.

## 3. Высокие дефекты

### H1. Перестройка страниц + подписки на события = падения и утечки

**Где:** `Shell.cs:1060-1112` (`RebuildPages`), `PageOverview.cs:66-67`, `PageUpdate.cs:68`, `Shell.cs:95-99` (`RaiseUpdateStateChanged`).

`RebuildPages` делает `p.View.Dispose()` для всех страниц, но `PageBase` не имеет `Dispose`/отписки. После смены темы (`Shell.cs:1148`), масштаба, папки (`SetRoot`, `:111`) или мастера (`:543`) старые страницы остаются подписанными на `Shell.UpdateStateChanged` и `Log.Appended`. Следующий `RaiseUpdateStateChanged` вызывает `RefreshState()` уже уничтоженной страницы: `_installCard.Visible`, `_stateTitle.Text` → `ObjectDisposedException` в UI-потоке → глобальный обработчик → диалог «Произошла ошибка». Плюс каждая перестройка навсегда оставляет в памяти старый набор страниц и контролов.

**Исправление:** `PageBase : IDisposable` с отпиской от всех событий; вызывать в `RebuildPages`; либо weak events.

### H2. Запись в RichTextBox из фонового потока

**Где:** `Core.cs:49-53` (`Log.Write` вызывает `Appended` в потоке писателя), `PageOverview.cs:66-67, 332-336` (`OnLog` → `_log.Append`), `UI.cs:813-835`.

Фоновые писатели: self-update (`SelfUpdate.cs:230/233/285`), проверка обновлений, сторож, загрузки. `LogView.Append` дёргает `TextLength/SelectionStart/AppendText/ScrollToCaret` — это SendMessage к окну, созданному в UI-потоке. В Release `CheckForIllegalCrossThreadCalls` выключен: либо тихое повреждение/потеря строк, либо блокировка фонового потока, пока UI занят (а он занят `Thread.Sleep(1200)` в `Ops.Start`). Исключение глотается `try { h(...) } catch { }` в `Log.Write`.

**Исправление:** в `OnLog` маршалить через `Shell.Ui`/очередь + таймер-насос; `LogView` не трогать из чужих потоков.

### H3. Долгие блокирующие операции в UI-потоке

**Где:** `PageStrategies.cs:171, 187`, `PageOverview.cs:114, 495, 503, 513`, `TrayToggleZapret` (`Shell.cs:444-457`), `PageSettings.cs:338, 348, 403-409`, `PageDiagnostics.cs:134`, `PageTgProxy.cs:312-342`, `PageTest.cs:659-670`, `PageTools.cs:263-279`.

Внутри: `Ops.Start` — `Thread.Sleep(400)` + `Thread.Sleep(1200)` + WMI (`Core.cs:1540-1557`); `Stop` — `sc stop` с таймаутом 20 с (`:1607`); `InstallService` — `sc stop/delete/create/start` (20-25 с каждый) + `Sleep(900)` (`:1693-1718`); `RunAction` — до 4×(12+12) с (`Diagnostics.cs:468-504`); автозапуск — `schtasks /Create` до 30 с (`Autostart.cs:39`); TCP timestamps — 2×`netsh` по 10 с (`Core.cs:1634-1646`); старт TG-прокси — до ~7 с (`TgProxy.cs:395-400`); `FindPython` — до 8 с на кандидата (`TgSource.cs:122`).

**Исправление:** все операции через `Shell.RunBackground` + прогресс + `Enabled=false`; `Thread.Sleep` заменить на ожидание состояния (SCM/порт/процесс) с таймаутом.

### H4. `PageSettings.RefreshState` запускает `schtasks.exe` каждые 5 секунд

**Где:** `PageSettings.cs:252-260` (`RefreshStartupStatus` → `Autostart.IsEnabled`), `:489`; `Autostart.cs:22-27` (`schtasks /Query`, таймаут 15 с); `Shell.cs:281-288` (таймер 5 с) → `RefreshStateAsync` → `Current.RefreshState()`.

**Исправление:** кэшировать состояние задачи (например, 30-60 с), выполнять в фоне, обновлять только при открытии страницы/после изменения.

### H6. «Проверка приложения» собирает DNS всех процессов, а не выбранного

**Где:** `AppProbe.cs:164-196` (`Watch`), `SiteGuard.cs:26, 119-123`; `PageSites.cs:156-221`.

`Watch` ставит `SiteGuard.AllowAllProcesses = true` и передаёт PID только в `RemoteIps(pid)`. `NewBrowserHosts` при `AllowAllProcesses` **не фильтрует** события по PID (фильтр `IsBrowser` включается только при `pidMatch.Success` и `!AllowAllProcesses`). В результате за 60 секунд собираются DNS-запросы всех приложений и браузеров в системе, а не выбранного. `SameApp(pid)`/`WithChildren(pid)` — мёртвый код, хотя именно они могли бы это исправить.

**Исправление:** извлекать `ClientPID`/`QueryName` из свойств события (`EventRecord.Properties`/`ToXml`) и фильтровать по `SameApp`/`WithChildren`; либо честно назвать функцию «все DNS за 60 с».

### H7. Строки с аннотациями `# TLS: …` попадают в список ускорения

**Где:** `PageSites.cs:487-498` (`Hosts()` отбрасывает только строки, начинающиеся с `#`), `:500-544` (`ProbeList` дописывает `host + "     # TLS: …"`), `:546-568` (`AddToList`), `SiteDoctor.cs:500-533` (`AddToUserList` не валидирует).

Кнопка «В мой список» передаёт эту строку целиком; `AddToUserList` только `Trim`/lower и дописывает в `list-general-user.txt`. В зависимости от парсера zapret такой хост либо не сработает, либо «повезёт» и первый токен будет принят; в любом случае файл засорён, а UI сообщает «Добавлено адресов: N». `AddToHosts` для таких строк не найдёт IP.

### H8. `TgProxy.Stop` убивает все копии TG WS Proxy

**Исправление:** останавливать только процессы, чей исполняемый путь лежит в `st.Dir`/`RootDir`; `StopProcessesInside` — правильный образец.

### H9. «Тихий режим» TG-прокси требует системный Python вопреки документации

**Где:** `TgSource.cs:163-170` (`Prepare` требует `FindPython()`), `:405-428` (`Start` берёт `BasePython()` — системный python из маркера/PATH), `:473-487` (`BasePython`), `README.md:236-239`, `docs/guide.md:43`.

README и guide утверждают: «Python в системе **не нужен**: менеджер скачивает портативный Python сам». В коде:

- `Prepare` при отсутствии системного Python сразу возвращает «Python 3 не найден. Установите Python с python.org…» — до скачивания портативного;
- `Start` запускает `BasePython()` (системный `pythonw.exe`), а `VenvPython` (`.venv\Scripts\pythonw.exe`) никогда не создаётся;
- портативный Python используется только для `pip`/проверки пакетов, а `PYTHONPATH` указывает на **несуществующий** `.venv\Lib\site-packages` (`:422-427`), поэтому прокси реально работает на системных пакетах.

На чистой машине без Python тихий режим не подготовить; на машине с Python — работает, но не так, как описано.

**Исправление:** либо действительно использовать `PortablePython` для запуска и `PortableSitePackages` в `PYTHONPATH`, либо убрать портативную затею и честно требовать Python. Проверять `IsPrepared` по фактическому `BasePython`.

### H10. Обновление zapret: частичная установка рапортуется как успех, отката нет

**Где:** `Update.cs:553-575` (`CopyPayload` ловит ошибку копирования и продолжает), `:483` (`Finish(true, ...)`), `:486-491` (в `catch` — `Finish(false)` без восстановления), `:430-434` (backup есть, но не используется для отката).

```csharp
try { File.Copy(file, dest, true); }
catch (Exception ex) { Log.Warn("Не удалось скопировать " + rel + ": " + ex.Message); }
...
Finish(true, "", summary, backupPath);
```

Если файл занят (`winws`/`WinDivert`), read-only или ACL не позволяет — копирование пропускается, но пользователь видит «Обновлено до версии X». При сбое после остановки ускорения (`:421-428`) служба уже остановлена, файлы частично заменены, ускорение не восстановлено; резервная копия лежит рядом, но её никто не откатывает.

**Исправление:** считать ошибки копирования; при >0 — `Finish(false)` + автоматический откат (`root → .failed`, `backup → root`) + перезапуск службы/стратегии в `finally`. Показывать список неудачных файлов.

### H11. Служба: успех без проверки запуска, `Stop` рапортует успех вслепую

**Где:** `Core.cs:1680-1727` (`InstallService`), `:1601-1619` (`Stop`).

- `sc create` после `sc delete` без retry: SCM удаляет службу асинхронно, `sc create` может вернуть 1072/1073; пользователь получает ошибку без повторной попытки.
- `ok = snap.Installed` — успех, даже если `sc start` не удался; статус может быть «остановлена».
- `Stop()`: `Proc.Run("sc.exe", "stop zapret", 20000); msg += "Служба zapret остановлена. ";` — `ExitCode` не проверяется, перехода в `Stopped` не ждёт, сразу `KillAll` → SCM видит аварийное завершение, а пользователю сказано «остановлена».

**Исправление:** ждать `StopPending → Stopped`; проверять коды; `ok = (status == "работает")`; при удалении — retry с backoff.

### H12. «Открыть .bat» исполняет стратегию от имени администратора

**Где:** `PageStrategies.cs:195-201`.

```csharp
Process.Start(new ProcessStartInfo(s.File) { UseShellExecute = true });
```

`ShellExecute` для `.bat` означает **запуск**, а не открытие в редакторе. Кнопка «Открыть .bat» запускает `cmd` с содержимым стратегии: в реальных файлах это `call service.bat ...` (проверка обновлений, игровой фильтр, TCP timestamps, `start /b`), плюс второй `winws.exe` вне учёта менеджера. Пользователь ожидает просмотр файла.

**Исправление:** открывать в блокноте/редакторе (`notepad.exe "file"`), либо переименовать в «Запустить .bat» с подтверждением.

### H13. Диагностика: деструктивные действия без подтверждения + ложная ошибка WinDivert

**Где:** `PageDiagnostics.cs:127-137` (`OnAction` без `Dlg.Confirm`, всегда `LogLevel.Ok`), `Diagnostics.cs:124-129` (проверка `wd.Installed`), `:468-504` (`RunAction`).

- «Удалить WinDivert», «Удалить конфликтующие службы» (GoodbyeDPI, discordfix_zapret, winws1/winws2), «Очистить кэш Discord» выполняются одним кликом без подтверждения; результат всегда показывается зелёным тостом, даже если `sc delete` вернул ошибку.
- «Зависший драйвер WinDivert»: условие `if (!winws && wd.Installed)`. `Installed` — это лишь наличие ключа/службы (`Core.cs:1351-1387`), состояние не проверяется. Остановленная demand-start служба `WinDivert` (нормальное состояние после остановки ускорения) даёт **ошибку** и предложение удалить драйвер. Ниже в том же файле (`Diagnostics.cs:221`) аналогичная проверка сделана правильно через `Status == "работает"`.
- Строка «Кэш Discord» имеет `Severity = Ok`, но кнопка действия на зелёной строке закрывает Discord и удаляет `Cache`/`Code Cache`/`GPUCache` (`Core.cs:2080-2118`).

**Исправление:** подтверждение для всех destructive actions, проверка кодов, кнопки только для Error/Warn, `wd.Status == "работает"` в проверке.

### H14. Версии: пре-релизы и буквенные суффиксы не различаются

**Где:** `Update.cs:215-256` (`Versions.Parts`), `SelfUpdate.cs:102-104`, `Core.cs:868`, `version.txt`.

`Parts("1.4.0-pre1") == [1,4,0] == Parts("1.4.0")`; `Parts("1.9.9d") == [1,9,9]`. Следствия:

- пользователям `1.4.0-pre1` финальный `1.4.0` **не предложат** (Compare = 0);
- `1.9.9d` не считается новее `1.9.9` (и наоборот), поэтому обновление на буквенные теги Flowseal (`README.md:287`) не работает;
- `version.txt = 1.3.0` при `AppInfo.Version = 1.4.0-pre1` и `FileVersion 1.4.0.0`; `build.ps1` печатает «версия 1.3.0» для dist;
- regex `[0-9]+(\.[0-9]+)*` принимает любой цифровой фрагмент (тег `2026-11-26` → «версия 2026»).

**Исправление:** SemVer-парсер с корректным сравнением pre-release и суффиксов, единый источник версии (генерировать `version.txt` из константы), пометка pre-release в UI.

## 6. Безопасность и модель угроз

Общий контекст: при обычном запуске приложение запрашивает elevation (`Program.cs:52-62`), а автозапуск идёт с `HIGHEST` (`Autostart.cs:37-38`); по README exe кладётся рядом с `service.bat` — в пользовательскую папку (по умолчанию `%LOCALAPPDATA%\ZapretManager\zapret`, `SetupWizard.cs:202-206`). `data\manager.ini` — user-writable конфиг, читаемый привилегированным процессом. Это создаёт класс атак «medium-integrity процесс пользователя → elevated выполнение».

### S1. [высокий] Отравление `manager.ini` → запуск произвольного exe с правами администратора при автозапуске

**Где:** `TgProxy.cs:175-181, 211-218, 391-394`; `Core.cs:958-966, 1556`; `Program.cs:46-48`; `Shell.cs:504-532`.

`TgExe` из конфига принимается без проверки владельца/ACL/подписи; `Root` — без проверки, что это доверенная папка. При `--autostart` (задача `/RL HIGHEST`, `Autostart.cs:37-38`) `RunAutostartBootstrap` сам вызывает `TgProxy.Start` и `ZapretOps.Start`. Любой процесс того же пользователя может записать `TgExe=C:\Users\Public\pwn.exe` (или создать папку с `service.bat` + `bin\winws.exe` и прописать `Root=`) → при следующем входе в Windows код выполнится админом без UAC.

**Исправление:** не хранить пути запуска в user-writable конфиге; проверять Authenticode/хэш и ACL (owner Administrators/SYSTEM) перед запуском; autostart — только из защищённого каталога.

### S2. [высокий] Задача `/RL HIGHEST` на exe из пользовательской папки

**Где:** `Autostart.cs:35-39`.

Сам механизм — легитимный UAC-friendly автозапуск, но действие задачи указывает на файл, который может перезаписать любой процесс пользователя (exe по умолчанию в `%LOCALAPPDATA%`). Замена exe → elevated-старт без UAC, устойчивое закрепление. Кавычки в `/TR` расставлены корректно (проверено разбором), проблема не в quoting, а в доверии к пути.

**Исправление:** установка в `Program Files` с ACL; в задаче — защищённая копия/лаунчер; проверка хэша/подписи; либо служба с корректным DACL вместо HIGHEST-задачи.

### S3. [высокий/средний] Самообновление: fail-open, TOCTOU, отсутствие подписи

**Где:** `SelfUpdate.cs:146-161, 224-238, 256-281`.

- `ExpectedSha256` при любой ошибке/404 возвращает `""`; `Apply` в этом случае проверяет только размер, `MZ` и `FileVersion` и **всё равно обновляется** (`Log.Warn("...нет checksums.txt...")`). Любая сетевая ошибка тихо понижает проверку.
- Хэш из `checksums.txt` публикуется тем же аккаунтом/релизом, что и exe — не аутентифицирует артефакт и не защищает от компрометации аккаунта. Authenticode отсутствует (exe не подписан — проверено `Get-AuthenticodeSignature`).
- TOCTOU: хэш проверяется на файле в `%TEMP%`, затем `cmd` копирует его позже; каталог `%TEMP%\ZapretManagerUpdate` доступен на запись процессам того же пользователя.

**Исправление:** fail-closed (без хэша/подписи не обновлять), подпись exe, каталог обновления с ACL, перепроверка хэша непосредственно перед копированием, отказ от `cmd`.

### S4. [средний] Архив zapret и `winws.exe` без проверки целостности

**Где:** `Update.cs:397-409, 643-651`; `Core.cs:1699-1701`.

Содержимое архива (`winws.exe`, `*.bat`) копируется в папку установки и запускается как служба LocalSystem. Хэшей/подписей нет ни для архива, ни для exe. TLS защищает канал, но не артефакт; компрометация GitHub-аккаунта Flowseal = RCE как SYSTEM.

**Исправление:** подписывать релизы и проверять Authenticode у `winws.exe`; pinned SHA-256; отказ от установки без проверки.

### S5. [средний] `UacTools.RestoreDefaults` читает непроверенный JSON из `%ProgramData%`

**Где:** `Core.cs:825-863`; ключ `--restore-uac` (`Program.cs:146-150`); `tools/restore-uac.ps1`.

Значения `ConsentPromptBehaviorAdmin`/`PromptOnSecureDesktop` берутся регуляркой из `C:\ProgramData\ZapretManager\uac-backup.json`, который **никто в коде не создаёт**. Каталог `ProgramData` по умолчанию разрешает пользователям создавать папки; файл может быть подложен заранее. При `0/0` UAC перестаёт спрашивать. Пользователь запускает документированную «восстанавливающую» команду, подтверждает UAC — и получает отключённый UAC. Запись идёт в HKLM.

**Исправление:** хранить бэкап в admin-only каталоге или в HKLM; проверять owner/ACL и допустимые значения (5/1); либо не трогать HKLM.

### S6. [средний] Секрет MTProto-прокси в командной строке

**Где:** `TgSource.cs:397-401` (`--secret`), `TgProxy.cs:38-45, 288-310`.

Командная строка процесса читается любым пользователем (сам менеджер читает её через WMI). Секрет прокси утекает; `Host/Port/Secret` из `%APPDATA%\TgWsProxy\config.json` не валидируются (только `Length == 32`) и подставляются в `tg://proxy?...`; подмена `config.json` = подключение к чужому прокси (MITM).

**Исправление:** передавать секрет через env/файл с ACL/stdin; валидировать hex-32, host = `127.0.0.1`, port 1..65535; предупреждать при ином host.

### S7. [средний] `CleanTemp` удаляет файлы elevated-процессом сквозь junction

**Где:** `Core.cs:787-814`; вызов `Program.cs:85`.

`Directory.GetFiles(..., AllDirectories)` следует по reparse point (проверено на .NET 4.8). `%TEMP%\ZapretManagerUpdate` создаётся непривилегированным процессом того же пользователя; junction на любой каталог → elevated-процесс удалит там все файлы старше 7 дней (в пределах ACL). Плюс TOCTOU между `FileInfo` и `Delete`.

**Исправление:** не рекурсировать; удалять только известные имена/верхний уровень; проверять `FileAttributes.ReparsePoint`; не чистить `%TEMP%` в elevated-процессе на старте.

### S8. [низкий] Прочее

- Именованные `Mutex`/`EventWaitHandle` без DACL (`Program.cs:70-81`): любой процесс пользователя может создать объект с тем же именем → менеджер считает, что уже запущен, и выходит (DoS); `FindWindow` по заголовку может активировать чужое окно.
- Поиск `sc.exe`/`schtasks.exe`/`cmd.exe` по имени (`Core.cs:205-211`, `Autostart.cs:24`): CreateProcess ищет в каталоге приложения/CWD раньше System32; подложенный `sc.exe` рядом с exe выполнится elevated (усиливает S1).
- `Program.cs:199` логирует все аргументы (секреты при появлении — в `manager.log`).
- `--elevated` снаружи лишь подавляет авто-повышение (прав не даёт), но ломает инвариант; `BuildElevatedArgs` (`:340-354`) не экранирует кавычки/пустые аргументы.
- `log`/`manager.ini`/`data` не имеют ограниченного ACL.

## 10. Что сделано хорошо

- **Один exe, без установки и зависимостей**, сборка встроенным `csc`, ресурсы и иконка вшиты; `longPathAware`, `dpiAware`, Common Controls v6.
- **Разбор реальных `.bat`**: все 21 `general*.bat` (`start "zapret: %~n0" /min "%BIN%winws.exe" … ^ …`) разбираются корректно — снятие кавычки, склейка `^`, многошаговое раскрытие `%VAR%`/`%~dp0`, кавычки внутри токенов; рабочая папка `bin` совпадает.
- **Токены игрового фильтра** эквивалентны эталону `service.bat` (disabled→12, all/tcp/udp).
- **Механизм `# >>>`/`# <<<` + baseline + `ApplyAfterUpdate`** продуман: добавления переживают обновление, старые маркеры вырезаются, новости разработчика считаются отдельно (кроме C2).
- **Обновление сохраняет пользовательские файлы**: `manager.ini/log`, `data/`, `*-user.txt`, `ipset-all` + `.backup`, `targets.txt`, `game_filter.enabled`, `check_updates.enabled`, exe менеджера (`Update.cs:578-598`); backup создаётся до копирования, служба останавливается.
- **TLS**: `Web.EnableModernTls` включает TLS 1.2/1.3; в путях обновления/скачивания проверка сертификата не отключена; `req.Proxy = null` — осознанное решение.
- **zip-slip**: `ZipFile.ExtractToDirectory` в .NET Framework 4.8 **сам отклоняет** выход за каталог (проверено экспериментом) — отдельная защита не нужна.
- **hosts**: резервная копия до записи, `Regex.Escape` при проверке существующих, только отсутствующие записи, `ipconfig /flushdns`.
- **Безопасность команд**: инъекций в `wevtutil` (константный `LogName`), `schtasks` (`/TR` quoting корректен), `sc create` (quoted ImagePath) не найдено; WQL экранирование `'` корректно.
- **UI**: кастомные контролы с `OptimizedDoubleBuffer`, GDI-объекты в `using`, одна иконка трея, корректное закрытие/сохранение конфига, `BeginInvoke` (без `Invoke`+Wait, т.е. без классического deadlock).
- **Диагностика**: 20+ осмысленных проверок (BFE, прокси, конфликтующие службы, DoH, hosts, целостность списков, зависший WinDivert), отчёт копируется, многие проблемы имеют кнопку исправления.
- **Журнал** с ротацией 512 КБ, глобальные обработчики исключений, `ReportCrash` не раскрывает стек пользователю.

## Приложение A. Воспроизведённые эксперименты

1. **Сборка.** `build.ps1` в temp-каталог → успех; корневой `ZapretManager.exe` занят запущенным приложением (ожидаемо для Windows); 5 warning'ов CS0649/CS0169.
2. **zip-slip.** Zip с записью `..\evil.txt` → `ZipFile.ExtractToDirectory` на .NET Framework 4.8 выбрасывает «Извлечение записи ZipEntry приведет к созданию файла за пределами указанного целевого каталога», файл не создаётся. **Защита есть.**
3. **Кодировка `.cmd`.** Скрипт с кириллицей: UTF-8 → выполняется; CP1251 (`Encoding.Default`) → `exit=1`, файл не найден; CP866 на данной машине тоже не сработал (cmd читает пакет как UTF-8). Вывод: `Encoding.Default` для `.cmd` непригоден.
4. **`ListChanges.AcceptAsOfficial`.** Harness: файл с блоком `added.com` → после «Принять» в файле только официальные строки; после `Load` `removed=[added.com]`. **Потеря подтверждена.**
5. **`ListAudit.Tidy`.** `10.0.0.0/8` → `10.0.0.0`; `^dns.google` → `dns.google`; `fc00::/7` удалён. **Порча подтверждена.**
6. **`netsh`.** На проверенной машине вывод английский (`RFC 1323 Timestamps : enabled`) — текущий парсер работает; на системе с другим MUI-языком возможен `null` (помечено как «требует проверки», не как факт).
7. **Живое состояние.** Служба `zapret` RUNNING, `winws.exe` PID 5324, `WinDivert` RUNNING, тихий TG-прокси PID 1260 (`pythonw` из `tgwsproxy-src\python`, порт 1080, `--secret` в командной строке). `SiteGuard=1`, но записей сторожа в логе нет.
8. **Junction.** `Directory.GetFiles(..., AllDirectories)` на .NET Framework 4.8 возвращает файлы по обе стороны junction (`link\deep\secret.txt` и `target\deep\secret.txt`) — это подтверждает M47; тестовый каталог удалён.
