# Zapret Manager 2.3.0 — сервисы, избранное, автолечение и ресурсы

## 1. Оценка по сервисам

- Сервис (группа `targets.txt`) считается рабочим, если прошло **не меньше 60%**
  его целей.
- Лучшая стратегия выбирается сначала по числу рабочих сервисов, затем по числу
  пройденных целей.
- В итоговой строке теста видно: `сервисов: X из Y`.
- Это ближе к реальности: один открытый адрес Discord не означает, что работает
  голосовой канал.

## 2. Поиск и избранное стратегий

- В «Стратегиях» появился поиск по названию и описанию.
- Звёздочка ★/☆ закрепляет стратегию в избранном (сохраняется в `manager.ini`,
  ключ `Favorites`).
- Фильтр «Только избранные».
- Счётчик «N из M».

## 3. Автолечение bypass

- В «Настройках → Запуск и автозапуск» есть переключатель **«Автолечение bypass»**
  (по умолчанию выключен).
- Если bypass был запущен, а `winws.exe` неожиданно завершился, менеджер
  перезапускает службу zapret или последнюю стратегию.
- Не более 3 попыток; после успешного запуска счётчик сбрасывается.
- Ручная остановка и тест стратегий отключают автолечение, чтобы оно не мешало.
- Настройка хранится в `manager.ini` (`AutoHeal=1`).

## 4. Монитор ресурсов

- На «Обзоре» карточка «Ресурсы»: PID, uptime и рабочий набор памяти
  `winws.exe` и `TG WS Proxy`.
- Значения обновляются раз в 5 секунд, без опроса каждый кадр.
- Если процесс не запущен — так и пишется.

## 5. Окно обновлений и затемнение

- Диалог подтверждения теперь рисуется в `Order::Foreground`, поэтому затемнение
  не накрывает само окно.
- При запуске показывается окно «Доступны обновления» со списком компонентов:
  Zapret Manager, zapret, TG WS Proxy — текущая и новая версия.
- Набор версий запоминается в `manager.ini` (`UpdateNoticeDismissed`), чтобы
  «Позже» не показывало одно и то же при каждом старте; новая версия снова
  открывает окно.
- При старте TG WS Proxy тоже проверяется на обновление.

## Проверки

35 unit-тестов, `--selftest`, `--diag`.
