# Внутреннее устройство Zapret Manager

Технические заметки для тех, кто читает или меняет код. Пользовательское руководство —
[../guide.md](../guide.md), история версий — [../../CHANGELOG.md](../../CHANGELOG.md),
подробности о прошлых исправлениях — [FIXES.md](FIXES.md).

## Слои и правило зависимостей

```
main.rs   CLI-режимы, UAC, один экземпляр, запуск UI
  ui/     egui/eframe: окно, страницы, трей, тема, виджеты
  engine/ вся логика без интерфейса
  util.rs версии, сортировка, SHA-256, время, валидация
```

- `engine/` не знает про `egui` — им можно пользоваться из CLI и тестов.
- `ui/` не вызывает Win32 напрямую, кроме `ui/tray.rs` и нескольких мест `app.rs`
  (HWND окна для иконки и тёмного заголовка).
- `main.rs` — тонкий диспетчер. Служебный режим `--apply-update` обрабатывается
  **до** журнала и до запроса UAC: это замена exe после самообновления.

## Поток данных: от стратегии до winws

```
general (ALT12).bat
  │ textfile::read_lines → BOM / UTF-16 / CP1251 / UTF-8
  │ 1) `set "K=V"` по всему файлу → переменные (+ GameFilterTCP/UDP из состояния)
  │ 2) первая строка с winws.exe, склейка по `^`
  │ 3) %~dp0 → <root>\, затем %NAME% (до 5 проходов)
  │ 4) снятие `^` (нужно для --dpi-desync-fake-tls=^!)
  │ 5) tokenize с сохранением кавычек; пустые *-user.txt выбрасываются
  ▼
bat::build_command_line → Command::raw_arg (без повторного экранирования), cwd = bin\
  ▼
winws.exe → WinDivert → правила применяются к первым пакетам соединения
```

Обратная операция (`bat::build_cmd_line`, экранирование `^ % ! & | < > ( )`) нужна
автоподбору: он пишет временный `.bat`, который потом можно запустить обычным
двойным кликом, вне менеджера.

## Ядро zapret: 1.x и 2.x

`ZapretInstall` хранит `core: Core`:

- `V1` — `bin\winws.exe` и стратегии `--dpi-desync…`; это единственное ядро, которым
  менеджер управляет;
- `V2` — `bin\winws2.exe`, каталог `lua\`, правила `--lua-desync`. Установка
  **распознаётся** (чтобы не писать «папка не найдена»), но стратегии не разбираются,
  служба не ставится, обновления на 2.x не предлагаются.

Правила, которые нельзя нарушать:

- явно выбранная папка (`--root`, `Root` в ini) имеет приоритет над автопоиском;
  автопоиск сначала ищет 1.x и только потом 2.x, чтобы не «терять» рабочую установку;
- `Release::is_supported()` = не prerelease **и** ядро 1.x. На нём построены
  `latest_supported_zapret()`, `list_supported_zapret()` и проверки в
  `update_now`/`install_fresh` (защита в глубину для ручного тега);
- версия 2.x берётся из имени папки: в релизе 2.0.0-rc `service.bat` всё ещё
  объявляет `LOCAL_VERSION=1.10.4`.

## Процесс, служба и состояние

- `OP_LOCK` сериализует start/stop/restart/install/remove: иначе «Стоп» может
  дождаться остановки службы уже после того, как параллельный «Запуск» поднял
  новый `winws.exe`, и убить его.
- `kill_winws` убивает только процессы, у которых в командной строке есть
  `<root>\`, и дополнительно сверяет путь к exe — защита от переиспользования PID.
- Служба: `CreateServiceW` (AUTO_START, LocalSystem), описание через
  `ChangeServiceConfig2W`, имя стратегии — в HKLM-значении ключа службы.
  При неудачном старте служба удаляется (откат).
- `RuntimeState` (`ops::get_state`) — снимок: процесс, служба, IPSet, игровой фильтр.
  Тяжёлые части (`netsh` для TCP timestamps) считаются в фоновом потоке и кладутся
  в состояние отдельно.

## Обновления

- Проверка: `list_releases` (GitHub API) → фильтр поддерживаемых релизов; первые
  отброшенные возвращаются в `UpdateCheckResult::skipped`, чтобы интерфейс мог
  объяснить, почему «2.0.0-rc» не предлагается.
- Установка: `trusted_github_url` → скачивание с прогрессом → SHA-256 (сверка с
  `digest` GitHub, если он есть) → `extract_zip` с лимитами (записи, файл, сумма) →
  `find_payload` (различает «нет папки zapret» и «это zapret 2.x») → проверка
  подписи `winws.exe` → остановка службы → бэкап папки → копирование с сохранением
  пользовательских файлов → перенос правок списков → рестарт.
- Самообновление менеджера: обязательный `checksums.txt`, проверка размера и `MZ`,
  запрет неподписанного обновления поверх подписанного, `WinVerifyTrust` с отзывом,
  безопасная замена exe (rename + helper `--apply-update`).

## TG WS Proxy: два режима

1. **exe** — поиск установки, порт и секрет из `%APPDATA%\TgWsProxy\config.json`,
   ссылка `tg://proxy` (секрет URL-кодируется), обновление с GitHub по архитектуре.
2. **тихий** — исходники Flowseal + embeddable Python 3.13.5, установка
   `httpx[http2]`, `certifi`, `cryptography`, запуск `proxy\tg_ws_proxy.py` через
   `pythonw.exe`. Маркер версии — `prepared.txt`; поиск процесса — `python[w].exe`
   с `tg_ws_proxy.py` и путём установки в командной строке.

## Интерфейс и фоновые задачи

- `App` + канал `Msg`: страницы, `spawn_bg`, прогресс, тосты, подтверждения.
  `spawn_bg` всегда отправляет `BusyDone` (в том числе при панике), поэтому счётчик
  занятости не залипает.
- Тяжёлое не выполняется в кадре: удаление компонентов, сетевые пробы сторожа,
  `netsh`, `schtasks`, проверка обновлений — в фоновых потоках.
- Перерисовка: 300 мс при занятости, 900 мс в покое, 3 с когда окно скрыто в трей.
- Трей — отдельный поток: скрытое окно, `Shell_NotifyIconW`, собственное меню
  (GDI, Segoe MDL2, масштаб по DPI), восстановление иконки по `TaskbarCreated`,
  `catch_unwind` в `wndproc`. Клик открывает окно через `egui::Context`
  (`Visible(true)` + `request_repaint()`), а не только через `Show`.

## Файлы и данные

```
data\manager.ini     настройки (key=value, merge-on-save)
data\manager.log     журнал (ротация 512 КБ в .log.1)
data\test-results.tsv отчёт последнего теста
data\lists\*.changes|*.baseline  ваши правки официальных списков
%TEMP%\ZapretManager\            временные файлы, бэкапы обновлений
%APPDATA%\ZapretManager\         запасное место, если папка exe недоступна
```

Формат `manager.ini` читается и правится вручную: неизвестные ключи сохраняются,
меняются только тронутые.

## Сборка и подводные камни

- GNU-тулчейн (`x86_64-pc-windows-gnu`) не линкует проект, если в пути есть
  кириллица или пробелы: задайте `CARGO_TARGET_DIR` в ASCII-папку (это делает
  `build.ps1` и CI). С MSVC не требуется.
- `build.rs` встраивает иконку, манифест и `VERSIONINFO` через `windres` (GNU)
  или `rc.exe` (MSVC). Версия приложения берётся из `Cargo.toml`
  (`env!("CARGO_PKG_VERSION")`) — дублировать её строкой нельзя.
- Шрифты (`segoeui.ttf`, `consola.ttf`, `segmdl2.ttf`) читаются из
  `%WINDIR%\Fonts`; если файла нет — остаются штатные шрифты egui.
- Скриншоты для документации: `--shot=<png> --shot-page=<ключ>`, где ключ —
  `overview`, `strategies`, `test`, `sites`, `tgproxy`, `settings`, `lists`,
  `update`, `diagnostics`, `tools`, `about`.

## Проверки

```powershell
cargo test --locked              # 51 тест + 1 сетевой (--ignored)
cargo test --locked -- --ignored # живой GitHub API: 2.x должен быть пропущен
cargo build --release --locked
ZapretManager.exe --limited --selftest   # 11 проверок, код возврата 0/1
ZapretManager.exe --limited --diag       # ~30 проверок окружения в журнал
pwsh tools/verify-exe.ps1 target/release/ZapretManager.exe  # метаданные exe
```

Тесты покрывают `.bat`-парсер, списки и их перенос, сравнение версий, определение
ядра, SHA-256, время, сетевые утилиты, резервные копии и отказ от zapret 2.x.

## Ограничения

- Поддерживается только ядро 1.x (см. выше); полноценная поддержка 2.x — отдельная
  большая работа (парсер `--lua-desync`, `lua\`, `winws2.exe`).
- Один экземпляр приложения на пользователя; портативный режим — папка exe.
- Телеметрии нет: сеть используется только для обновлений и проверок по действию
  пользователя.
